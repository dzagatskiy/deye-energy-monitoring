# Energy Monitor

iOS-застосунок і віджети для моніторингу гібридного інвертора Deye (SUN-6K-SG03LP1-EU) через Deye Cloud: стан мережі, SOC, навантаження, PV, облік відключень, спожита енергія, прогноз автономності.

## Структура

| Шлях | Що там |
|---|---|
| `Packages/EnergyCore` | Уся бізнес-логіка (Swift Package, лише Foundation): моделі, клієнт Deye Cloud, облік відключень, розрахунки, сховище, сервіс оновлення. Має unit-тести |
| `App/` | SwiftUI-застосунок: підключення, огляд, історія відключень, налаштування |
| `Widgets/` | WidgetKit: Small / Medium / Large і Lock Screen (circular, rectangular, inline) |
| `Shared/` | Код, спільний для застосунку й віджета: App Group, Keychain, вибір інвертора (App Intent), стиль |
| `Config/` | Info.plist і entitlements |
| `docs/` | Мапінг полів Deye Cloud, ADR |
| `scripts/` | `test.sh`, `build.sh`, `deye_spike.py` (запис знеособлених відповідей API у фікстури) |

## Команди

```bash
scripts/test.sh     # unit-тести EnergyCore
scripts/build.sh    # збірка застосунку і віджетів для iOS Simulator
```

`build.sh` явно використовує `/Applications/Xcode.app`, тож налаштування `xcode-select` можна не змінювати.

## Перший запуск

1. **Ключі розробника (один раз).** Застосунок покаже 3 кроки й кнопку «Відкрити developer.deyecloud.com». Створіть Application, скопіюйте AppId і AppSecret і натисніть «Вставити»: ключі розпізнаються з будь-якого скопійованого тексту. Для власної збірки ключі можна вбудувати через `Config/Secrets.xcconfig`, тоді цей крок пропускається. Деталі: [docs/deye-app-credentials.md](docs/deye-app-credentials.md).
2. **Вхід.** Email, пароль і регіон Deye Cloud, перемикач «Запам'ятати пароль». Пароль зберігається лише як SHA-256, і лише якщо перемикач увімкнено.
3. Застосунок сам знайде інвертори (`/station/listWithDevice`). Для кожного задайте назву, ємність батареї та мінімальний SOC.
4. Додайте віджет і в «Редагувати віджет» виберіть інвертор.

Щоб запустити на iPhone, потрібен Apple Developer Team. Bundle ID (`ua.energymonitor.app`) і App Group (`group.ua.energymonitor`) треба замінити на зареєстровані у вашому акаунті.

## Обмеження (чесно)

- **Кеш.** Дані зберігаються на iPhone (90 днів) і спільні з віджетом. Новий запит до Deye робиться лише тоді, коли там міг з'явитися новий кадр (~раз на 5.8 хв), хоч би хто оновлював: застосунок, віджет чи фон. «Потягнути, щоб оновити» обходить кеш.
- **Ліміти Deye.** Не більше 60 запитів/хв і опитування раз на 1–2 хв. Застосунок тримає запас (50/хв застосунок + 10/хв віджет), а після HTTP 429 робить паузу.
- **Частота даних.** Deye Cloud отримує кадр від логера приблизно раз на 5.7 хв, тому межі відключень визначаються з точністю ±3 хв.
- **Фон iOS.** Застосунок не може постійно опитувати API у фоні. Віджет оновлюється за бюджетом WidgetKit (приблизно раз на 15+ хв), фонове оновлення запускається на розсуд iOS. Відключення, пропущені у фоні, **відновлюються з історії Deye** при наступному оновленні, тож історія повна, але сповіщення можуть запізнюватися.
- **Без інтернету на дачі** Deye Cloud не отримує даних. Локальний режим (Solarman V5 напряму з логера) запланований, але ще не реалізований.
- **Сповіщення** локальні: світло зникло, світло повернулось, низький і критичний заряд. Вони приходять, коли iOS запускає застосунок, віджет або фонове оновлення, тож можуть запізнюватися. Подію, виявлену пізно, сповіщення подає з її справжнім часом, а пропущене цілком відключення — одним підсумком. Миттєві сповіщення потребують колектора на дачі й push-сервера.
- Екран статистики з графіками ще не реалізований.
